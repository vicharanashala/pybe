A1 "The Panchatantra Mirror"
Python Concept: Introspection, Reflection & Metaclasses Manifesto Level: 3–4 | Jonasan 
Type: Structured Inquiry
What This Is
A complete learning module that teaches Python's self-inspection capabilities the inspect 
module, dir(), hasattr(), getattr(), __dict__, and eventually metaclasses using the 
ancient Panchatantra story of the clever rabbit and the lion as the philosophical anchor. The 
Panchatantra is explicitly listed in the mind map as an unclaimed domain under "Folklore," making 
this the first PR to claim it.
The Four Pillars
Why (Theoretical Anchor): The Panchatantra story "The Clever Rabbit and the Lion" is not a 
children's tale it is a lesson in weaponizing self-awareness. The rabbit, physically outmatched, 
doesn't fight the lion. He shows the lion his own reflection in a well. The lion, seeing what appears 
to be a rival lion, charges and drowns himself. The rabbit wins by making his opponent confront its 
own image. This is the philosophical root of Python's introspection system: a program that can 
examine itself at runtime is a program that can outsmart rigid, static systems. The moment a Python 
object can look at itself and describe its own capabilities, it becomes as powerful as the rabbit.
Anchor (Interdisciplinary Mapping): Folklore (Panchatantra) → Reflection as tactical power → 
Python's inspect module and metaclass system. The rabbit's use of the well-mirror maps directly 
to Python's ability to examine its own objects using dir(), type(), 
inspect.getmembers(), and __dict__ at runtime.

Trigger (Case Study The Problem):
You are building a hospital's patient record processing system. This system receives 
patient objects from three different hospital branches. Each branch sends a different 
version of the Patient object: Branch A's version has billing_code, Branch B's 
version has insurance_id, and Branch C's version has both. At runtime, your 
processing engine must figure out what it's holding and decide how to handle it 
without crashing if a field doesn't exist.
The constraint: you are NOT allowed to ask any hospital which version they sent. You 
cannot use isinstance(). You cannot use try/except as your primary logic. 
You must look at the object's own reflection.
How does a program examine itself?
This problem forces the learner, out of necessity, to discover: dir(obj) to list all attributes, 
hasattr(obj, 'field') to safely check existence, getattr(obj, 'field', 
default) to safely retrieve, obj.__dict__ to see the raw attribute map, and finally 
inspect.getmembers(obj) for a complete inventory.
Reality (Software Engineering Depth): Demonstrate Python's functools.lru_cache it 
introspects its own call history at runtime to make eviction decisions. Then build a metaclass that 
auto-logs every method call on any class that inherits from it this is a real production pattern 
used in ORMs, audit systems, and middleware. Show hardware tie-in: a CPU's branch predictor 
does the same thing it maintains a history table of past branch outcomes and inspects that history 
to predict future execution paths. This is hardware-level introspection. Tie the metaclass pattern to 
how Django's ORM builds model fields by inspecting class definitions at class-creation time.

A2 "The DNA Helix"
Python Concept: Recursion, Call Stack, Stack Frames & Memory Limits Manifesto Level: 3–
4 | Jonasan Type: Structured Inquiry
What This Is
A learning module that uses the structure of DNA specifically Linus Pauling's discovery of the 
alpha-helix in 1951 to teach recursion, call stacks, Python's recursion limit, and how to convert 
recursive algorithms to iterative ones for memory safety. Biology is listed in the mind map 
("Protein Structures, ATCG") as a domain but has no PRs claiming it yet.
The Four Pillars
Why (Theoretical Anchor): DNA doesn't store genetic instructions as a flat linear string it folds 
onto itself. A protein's function is determined not by its amino acid sequence alone, but by the shape 
that sequence folds into. Each fold references the shape of previous folds. This is structurally 

recursive. Linus Pauling, studying protein structures in 1951, discovered the alpha-helix not by 
reading sequence data but by realizing that the physical shape was self-referential at every scale. 
Life itself uses recursion as its primary organizational strategy. A Python function that calls itself is 
not a programming trick it is the most natural structure in biology.
Anchor (Interdisciplinary Mapping): Molecular Biology → DNA's hierarchical folding pattern 
→ Python recursion. Each level of protein folding (primary → secondary → tertiary → quaternary 
structure) maps to a recursive call going deeper and deeper, with the base case being the innermost 
stable fold.
Trigger (Case Study):
A DNA sequencing lab is processing a gene. The gene is encoded in segments. Each 
segment, before it can be decoded, requires you to first decode a "template segment" 
from earlier in the strand. That template segment, in turn, requires another template.
You receive Segment A. To decode A, you need to first decode Segment B. To decode B, 
you first need Segment C. Segment C has no dependency it is the ground truth.
Write a decoder. Your system must handle this chain of dependencies.
New constraint: the lab's sequencer has just detected a gene with 15,000 nested 
segment references. Your decoder crashes. Why? What does Python's memory have to 
do with gene length?
This forces discovery of: recursion with a base case, call stack growth, 
sys.getrecursionlimit() (default 1000), RecursionError, 
sys.setrecursionlimit() and why blindly raising it is dangerous (each frame = memory), 
and finally converting to an iterative approach using an explicit stack (collections.deque).
Reality (Software Engineering Depth): Use tracemalloc to demonstrate live memory growth 
per recursive call. Show exactly how many bytes each stack frame consumes. Demonstrate 
sys.getrecursionlimit() and sys.setrecursionlimit(). Then convert the 
recursive decoder to an iterative one using collections.deque as an explicit stack show 
the memory profile is now flat. Hardware tie-in: CPUs have a hardware call stack (the return 
address stack buffer) with a fixed depth of ~16–30 entries. Buffer overflow attacks exploit what 
happens when this stack is exceeded. Python's software recursion limit exists for the same reason 
hardware stacks have limits.

import sys
import tracemalloc
from collections import deque
# 1. Recursive version (elegant but limited)
def decode_segment(segment_id, gene_map):
    segment = gene_map[segment_id]
    if segment['dependency'] is None:  # Base case
        return segment['data']
    dependency_data = decode_segment(segment['dependency'], gene_map)
    return decode(segment['data'], dependency_data)
# 2. Show the crash
sys.setrecursionlimit(10)  # Force early failure to demonstrate
# 3. Iterative version (memory-safe)
def decode_iterative(start_id, gene_map):
    stack = deque()
    current = start_id
    while gene_map[current]['dependency'] is not None:
        stack.append(current)
        current = gene_map[current]['dependency']
    result = gene_map[current]['data']
    while stack:
        seg_id = stack.pop()
        result = decode(gene_map[seg_id]['data'], result)
    return result
A3 "The Fellowship's Graph"
Python Concept: Graph Theory, Pathfinding & Dijkstra's Algorithm Manifesto Level: 4 | 
Jonasan Type: Dilemma (no single correct answer)
What This Is
A learning module using Tolkien's "The Lord of the Rings" specifically the Fellowship's route 
decision at Caradhras/Moria to teach graph representation, weighted edges, priority queues, and 
Dijkstra's shortest path algorithm. "Lord of the Rings" is listed in the mind map under Pop Culture 
Integration but has no implementation yet.
The Four Pillars
Why (Theoretical Anchor): Tolkien's Fellowship does not choose their route randomly. At 
Caradhras, Saruman blocks the mountain pass with a storm the edge weight of that route 
suddenly increases to near-infinity. The Fellowship is forced to reconsider. Moria (Mines of 
Khazad-dûm) is shorter in distance but carries a different kind of cost: danger, darkness, and 
unknown threats. Gandalf chooses Moria knowing the "distance" is shorter but the "risk cost" is 
high and uncertain. This is exactly what Dijkstra's algorithm does it continuously re-evaluates 
paths as new information about edge costs becomes available, seeking the minimum total cost path, 
where "cost" can be any quantifiable trade-off, not just distance.

Anchor (Interdisciplinary Mapping): Literature (Tolkien/LOTR) → Strategic route planning 
under dynamic constraints → Weighted graph traversal and Dijkstra's algorithm. The key insight: 
edge weights in real graphs are not always distance. They can be risk, time, moral cost, resource 
expenditure any quantifiable trade-off.
Trigger (Case Study):
A disaster relief logistics coordinator must route emergency medical supplies from a 
central depot (Mumbai) to a flood-affected village (Kolhapur). There are 7 possible 
routes, each with two costs: travel time (in hours) and risk score (bridges may be 
damaged, roads may be flooded each has a probability of failure).
Route 3 is fastest at 4 hours but has a 60% chance of a bridge collapse. Route 6 is safe 
but takes 9 hours. Route 2 is 6 hours and has a 20% risk.
Question 1: How do you represent this network as a data structure? Question 2: How 
do you find the path that minimizes total travel time? Question 3: How do you find the 
path that minimizes total risk? Question 4: How do you find a path that balances both? 
Is there a single "correct" answer?
Question 4 makes this a Dilemma (Jonasan type) there is no objectively correct answer. The 
learner must make a value judgment about how to weight competing costs. This is where Tolkien 
comes back in: Gandalf made a moral judgment, not a mathematical one.
Reality (Software Engineering Depth): Implement the graph as an adjacency dictionary. 
Implement Dijkstra's with heapq (Python's built-in min-heap). Show the time complexity: O((V 
+ E) log V). Demonstrate with timeit how performance degrades on a dense vs sparse 
graph. Hardware tie-in: CPU schedulers use priority queues (Completely Fair Scheduler in Linux) 
to manage process execution the same data structure (heapq) underlies both the Fellowship's 
route and the Linux kernel's process scheduler.

import heapq
def dijkstra(graph, start, cost_key='time'):
    # graph = {'Mumbai': {'Pune': {'time': 2, 'risk': 0.1}, ...}, ...}
    distances = {node: float('inf') for node in graph}
    distances[start] = 0
    priority_queue = [(0, start)]

    previous = {}
    while priority_queue:
        current_cost, current_node = heapq.heappop(priority_queue)
        for neighbor, edge_data in graph[current_node].items():
            cost = edge_data[cost_key]
            new_cost = current_cost + cost
            if new_cost < distances[neighbor]:
                distances[neighbor] = new_cost
                previous[neighbor] = current_node
                heapq.heappush(priority_queue, (new_cost, neighbor))
    return distances, previous
A4 "The Nashika Taal Engine"
Python Concept: Loops, Generator Functions, Lazy Evaluation & Threading Manifesto 
Level: 3–4 | Jonasan Type: Structured Inquiry
What This Is
This is the PR that fully implements the Nashik Dhol connection that the manifesto explicitly 
mentions but no contributor has yet built. It uses the taal (rhythmic cycle) of Nashik Dhol 
percussion to teach the philosophical difference between a for loop (pre-computed, memory-
heavy) and a generator function (computed on demand, memory-light), then escalates to threading 
and the GIL.
The Four Pillars
Why (Theoretical Anchor): A master Nashik Dhol player does not memorize every individual 
beat of a 10,000-beat performance. They internalize the rule that generates the pattern. The taal 
(rhythmic cycle, like a 16-beat Teentaal) is the formula, not the sequence. The player generates each 
beat on demand, in the moment, using the rule. This is the philosophical heart of Python's generator 
functions: instead of pre-computing and storing all values in memory (like writing out all 10,000 
beats on paper), a generator stores only the rule and computes each value lazily, on demand. 
range(10000) generates nothing in advance. The rule is the data structure.
Anchor (Interdisciplinary Mapping): Indian Classical Music → Nashik Dhol → Taal (rhythmic 
formula) → Generator functions (yield) as lazy, rule-driven computation. The synchronization of 
multiple dhol players maps to Python threading.
Trigger (Case Study):
A music system must simulate three Nashik Dhol players performing simultaneously: - 
Player 1 strikes every 2 beats - Player 2 strikes every 3 beats - Player 3 strikes every 5 
beats
Task 1: After how many beats does everyone strike at the same moment? Task 2: Now 
simulate this for 1,000,000 beats. Generate every synchronization point. Your system 
has only 64MB of RAM.
If you generate a list of all 1,000,000 beats, you run out of memory. How do you 
generate the sequence without ever storing it?

Task 3: The three players are in different locations and must play simultaneously via a 
network. How do you coordinate them in code?
Task 1 teaches: LCM (Least Common Multiple), math.lcm(). Task 2 forces the discovery of 
generators (yield) the learner cannot use a list for 1M items in 64MB. Task 3 introduces 
threading.Thread and threading.Event for synchronization.
Reality (Software Engineering Depth): Show memory comparison using sys.getsizeof(): a 
list of 1M integers vs a generator object (the list is megabytes; the generator is ~112 bytes). 
Demonstrate Python's GIL and why threading doesn't give true CPU parallelism for compute-
bound tasks. Introduce multiprocessing as the true parallelism tool. Hardware tie-in: audio 
hardware uses ring buffers circular buffers with a fixed size that overwrite old data. Implement 
one using collections.deque(maxlen=n) this is how audio drivers manage sample 
buffers at the firmware level.

A5 "Newton's Prism & The Bit Painter"
Python Concept: Bitwise Operators, Hexadecimal & Binary Memory 
Representation Manifesto Level: 3–4 | Jonasan Type: Structured Inquiry
What This Is
A module using Isaac Newton's prism experiment and Color Theory (listed in the mind map under 
Philosophical Frameworks) to teach bitwise operators AND (&), OR (|), XOR (^), left shift 
(<<), right shift (>>) and binary/hexadecimal number representation. The philosophical insight 
is that Newton didn't add color to white light he revealed what was already there. Similarly, 
bitwise operators don't create data they reveal structure that was always inside the number.
The Four Pillars
Why (Theoretical Anchor): When Isaac Newton passed white light through a prism in 1666, he 
discovered that white light already contained all colors. The prism was not a creative tool it was 
a revealing tool. It separated what was always there. This is the exact philosophy of bitwise 
operations: a 32-bit integer doesn't hold "one number" it holds 32 independent binary states, each 

waiting to be extracted with the right mask. Hexadecimal notation (0xFF8800) is not a different 
number it is the same number viewed through a different prism, one that makes the byte 
boundaries visible to human eyes.
Anchor (Interdisciplinary Mapping): Color Theory & Physics (Newton's Optics) → 
Decomposition of compound wholes into component parts → Bitwise masks as computational 
prisms that reveal hidden structure within integers.
Trigger (Case Study):
You are a digital archivist restoring a collection of 1980s digital artworks. The original 
artist stored an entire RGB color in a single 32-bit integer using a compact format from 
1987: - Bits 24–31: Alpha channel (transparency) - Bits 16–23: Red channel - Bits 8–
15: Green channel - Bits 0–7: Blue channel
Example: the integer 0xFFCC6600 represents Alpha=255, Red=204, Green=102, 
Blue=0.
Your task: build a color decoder. Given any packed integer, extract all four channels.
Rules: No string parsing. No converting to binary strings. No splitting. You must work 
with the integer itself using mathematical operations.
Bonus: Build an encoder that takes R, G, B, A values and packs them back into a single 
integer.
This forces discovery of: hex literals (0xFF), right shift (>>) to move bits into position, AND mask 
(& 0xFF) to isolate the last 8 bits, left shift (<<) for encoding, OR (|) for combining channels.
Reality (Software Engineering Depth): Python's struct module for packing/unpacking raw 
bytes used in network protocol implementations, binary file parsers, and hardware interfaces. 
Live demo: open and parse the first 14 bytes of an actual BMP file header. The BMP header 
contains image width, height, and color depth packed as bitfields this is genuine file format 
reverse engineering at the binary level. Hardware tie-in: MMIO (Memory-Mapped I/O) registers in 
microcontrollers are controlled exactly this way a single 32-bit register controls multiple 
hardware features through bitmasks. Show a GPIO control register example.

A6 "The Buddhist Garbage Collector"
Python Concept: Variable Scope, Reference Counting, Circular References & 
weakref Manifesto Level: 4 | Jonasan Type: Structured Inquiry
What This Is
The manifesto references Buddhism as an anchor for variable existence but doesn't fully 
operationalize it. This PR goes deeper: Buddhist philosophy of Anicca (impermanence) explains not 
just why variables should have purpose, but why they must eventually cease. Python's garbage 
collector is, philosophically, the principle of Anicca made computational. A variable that clings to 
memory beyond its useful life causes suffering (memory leaks). The weakref module is the 
Buddhist practice of non-attachment made into code.
The Four Pillars
Why (Theoretical Anchor): Anicca the Buddhist concept of impermanence states that all 
conditioned phenomena arise, persist for a time, and must cease. Clinging (upadana) to what must 
cease causes suffering (dukkha). In software, an object that cannot be garbage collected because 
some reference clings to it beyond its useful life is not just wasteful it is a system in suffering 
(memory leak, degraded performance, eventual crash). Python's reference-counting garbage 
collector embodies Anicca mechanically: when an object's reference count drops to zero, it ceases 
it does not "die," it simply stops being held. The weakref module allows you to reference an 
object without preventing its natural cessation the software equivalent of non-attachment.
Anchor (Interdisciplinary Mapping): Buddhist Philosophy → Anicca (Impermanence) + 
Upadana (Clinging) → Python's gc module, reference counting, circular references as clinging, 
weakref as non-attachment.
Trigger (Case Study):
A hospital patient management system creates a Patient object and a Ward object. 
When a patient is admitted, the ward adds the patient to its roster 
(ward.patients.append(patient)). The patient also keeps a reference to 
their ward (patient.ward = ward).
When the patient is discharged, the system does:
del patient
del ward
Both variables are deleted. Memory should be freed. But your memory profiler shows the memory 
is never freed. The patient and ward are still "alive" in memory even though no one is holding 
them.
Why? What is preventing the garbage collector from releasing them?
How do you model a relationship between two objects where each knows about the other, but 
where destroying one does not trap the other in memory forever?
This forces discovery of: circular references (A → B, B → A means neither reaches zero), 
sys.getrefcount() to count references, gc.collect() to manually trigger collection, 

gc.get_referrers() to find what's holding an object, and finally weakref.ref() and 
weakref.WeakValueDictionary as the solution.
Reality (Software Engineering Depth): Live demonstration using tracemalloc to prove the 
memory leak. Manual gc.collect() call showing it can resolve cycles but at a performance 
cost. Show the __del__ method as an object's "last rites" and why it is dangerous in circular 
reference scenarios. Hardware/embedded tie-in: MicroPython on a Raspberry Pi Pico has no OS-
level memory recovery. A circular reference in an embedded loop is fatal the device will silently 
corrupt or freeze. Show the weakref.WeakValueDictionary as the production pattern for 
object registries.

What This Is

        self.offset = 0
        self.size = size
    def allocate(self, n_bytes):

        address = ctypes.addressof(self.pool) + self.offset

module.exports = function authenticate(req, res, next) {
  const token = req.headers.authorization?.split(' ')[1];
  if (!token) return res.status(401).json({ error: 'No token' });
  try {
    req.user = jwt.verify(token, process.env.JWT_SECRET);
    next();
  } catch {
    res.status(401).json({ error: 'Invalid token' });
  }
};

B6 Spaced Repetition System (SM-2 Algorithm)
Scenario Review Scheduler Based on Forgetting Curve Engineering Complexity: Medium | 
Priority: Medium
What to Build
The SM-2 algorithm (used by Anki) schedules each scenario for review based on how well the 
learner did and how long ago they last saw it. Scenarios with high scores get longer intervals; 
scenarios with low scores come back sooner.
Backend Service (server/src/services/spacedRepetition.js):
function calculateNextReview(lastScore, currentInterval, easeFactor) {
  // SM-2 algorithm
  const quality = Math.round((lastScore / 100) * 5);  // convert to 0-5 scale
  
  let newInterval;

  if (quality < 3) {
    newInterval = 1;  // Review tomorrow learner struggled
  } else if (currentInterval === 0) {
    newInterval = 1;
  } else if (currentInterval === 1) {
    newInterval = 6;
  } else {
    newInterval = Math.round(currentInterval * easeFactor);
  }
  
  const newEaseFactor = Math.max(1.3, 
    easeFactor + 0.1 - (5 - quality) * (0.08 + (5 - quality) * 0.02)
  );
  
  const nextReviewDate = new Date();
  nextReviewDate.setDate(nextReviewDate.getDate() + newInterval);
  
  return { nextReviewDate, newInterval, newEaseFactor };
}

review today. Sorted by urgency (overdue first). Each card shows when it was last attempted and 
the score from that attempt.

C2 The Domain Mapper (Rhizomatic Path Visualizer)
D3.js Force-Directed Graph of Each Learner's Personal Learning Network Engineering 
Complexity: Medium-High | Priority: High
What This Is
The manifesto explicitly states the learning model is "rhizomatic" no single correct path, a 
network where every entry point is valid. This PR makes that network visible. Each learner gets a 
personal D3.js force-directed graph showing: which domains they entered from (music, biology, 
folklore), which Python concepts they discovered, and the connections between them. Two learners 
who learned recursion one through DNA folding, one through Panchatantra will have 
completely different-looking graphs. This makes the manifesto's philosophy literally visible.
What to Build
D3.js Component (client/src/components/DomainMapper.jsx): The graph has three 
node types:
•
Domain nodes (large, colored by domain: Biology=green, Music=orange, Folklore=gold) 
where the learner entered
•
Concept nodes (medium, blue) Python constructs discovered
•
Connection edges labeled with the scenario that connected domain to concept
import * as d3 from 'd3';
import { useEffect, useRef } from 'react';
export function DomainMapper({ learnerGraph }) {
  const svgRef = useRef();
  useEffect(() => {
    const svg = d3.select(svgRef.current);
    const { nodes, links } = learnerGraph;
    const simulation = d3.forceSimulation(nodes)
      .force('link', d3.forceLink(links).id(d => d.id).distance(120))
      .force('charge', d3.forceManyBody().strength(-300))
      .force('center', d3.forceCenter(400, 300));
    const link = svg.append('g').selectAll('line')
      .data(links).enter().append('line')
      .style('stroke', '#aaa').style('stroke-width', 2);

    const node = svg.append('g').selectAll('circle')
      .data(nodes).enter().append('circle')
      .attr('r', d => d.type === 'domain' ? 20 : 12)
      .attr('fill', d => d.type === 'domain' ? domainColors[d.domain] : 
'#4A90D9')
      .call(d3.drag()  // Make nodes draggable
        .on('start', dragStart)
        .on('drag', dragged)
        .on('end', dragEnd));
    simulation.on('tick', () => {
      link.attr('x1', d => d.source.x).attr('y1', d => d.source.y)
          .attr('x2', d => d.target.x).attr('y2', d => d.target.y);
      node.attr('cx', d => d.x).attr('cy', d => d.y);
    });
  }, [learnerGraph]);
  return <svg ref={svgRef} width={800} height={600} />;
}
Backend Graph Data Endpoint:
// GET /api/users/:id/learning-graph
router.get('/learning-graph', authenticate, async (req, res) => {
  const sessions = await Session.find({ userId: 
req.user.id }).populate('scenarioId');
  
  const nodes = new Map();
  const links = [];
  for (const session of sessions) {
    const scenario = session.scenarioId;
    
    // Add domain node
    if (!nodes.has(scenario.domain)) {
      nodes.set(scenario.domain, { id: scenario.domain, type: 'domain', domain: 
scenario.domain });
    }
    
    // Add concept node
    if (!nodes.has(scenario.pythonConcept)) {
      nodes.set(scenario.pythonConcept, { id: scenario.pythonConcept, type: 
'concept' });
    }
    
    // Add link from domain to concept
    links.push({
      source: scenario.domain,
      target: scenario.pythonConcept,
      scenarioTitle: scenario.title,
      score: session.scores.total
    });
  }
  res.json({ nodes: Array.from(nodes.values()), links });
});

function calculateXP(session) {
  const baseXP = session.scores.total;                    // 0-100 base
  const hintPenalty = session.hintsUsed * 5;             // -5 XP per hint used

  return Math.max(0, baseXP - hintPenalty + speedBonus + reflectionBonus + 
firstAttemptBonus);
}

C10 Case Study Template Enforcer

What to Build
A JSON schema and validation layer that enforces the structure of every new scenario submitted.

Scenario Schema Validation (server/src/validation/scenarioSchema.js):
const Joi = require('joi');
const scenarioSchema = Joi.object({
  title: Joi.string().min(10).max(100).required(),
  domain: Joi.string().valid(
    'Biology', 'Music', 'Folklore/Panchatantra', 'Literature', 
    'Philosophy/Buddhism', 'Pop Culture/Harry Potter', 'Pop Culture/LOTR',
    'Pop Culture/Avengers', 'Physics', 'Psychology', 'Linguistics',
    'Culinary', 'Sports', 'Other'
  ).required(),
  philosophicalAnchor: Joi.string().min(50).required()
    .messages({ 'string.min': 'Theoretical anchor must be at least 50 

characters. Explain the WHY deeply.' }),
  interdisciplinaryMapping: Joi.string().min(30).required(),
  caseStudy: Joi.string().min(100).required()
    .messages({ 'string.min': 'Case study must be at least 100 characters. Write 
a full scenario.' }),
  jonsasanType: Joi.string().valid('Structured Inquiry', 'Design Thinking', 
'Dilemma').required(),
  targetConstructs: Joi.array().items(Joi.string()).min(1).max(5).required(),
  hints: Joi.array().items(
    Joi.object({
order: Joi.number().integer().min(1).max(5).required(),
text: Joi.string().min(20).required()
    })
  ).min(3).max(5).required(),
  scoringRubric: Joi.object({
    reasoning: Joi.number().min(30).max(50).required(),
    code: Joi.number().min(20).max(40).required(),
    reflection: Joi.number().min(20).max(40).required()
  }).required(),
  reflectionPrompts: 
Joi.array().items(Joi.string().min(20)).min(3).max(5).required(),
  engineeringRealityLevel: Joi.number().min(1).max(5).required(),
  engineeringRealityDescription: Joi.string().min(50).required()
    .messages({ 'string.min': 'Describe the real engineering depth. Hardware? 
Memory? Firmware? Make it specific.' })
});
