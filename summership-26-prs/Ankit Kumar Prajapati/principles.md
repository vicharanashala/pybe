# Design Principles 

## Principles Followed
*   **Concepts Before Syntax:** The module introduces the intuitive logic of iteration (searching a dark theater) before ever exposing the learner to Python code. 
*   **Natural Concept Flow:** `for` and `while` loops are allowed to emerge naturally from the narrative (e.g., contrasting a fixed 20-row water distribution with an unknown row search) rather than being forced mechanically.
*   **Incremental Code Building:** The transition to code does not happen all at once. The logic is broken down incrementally (Starting State, Condition, Action, Update Step) to prevent cognitive overload.
*   **Single-Topic Scope (MVP Focus):** To ensure a simple, meaningful, and feasible Minimum Viable Product (MVP), the scope was strictly restricted to introductory case studies and core concepts, dropping advanced modular expansions.
*   **Ending in Real Code:** The module ensures the learner bridges the gap between the analogy and actual programming by concluding with applicable Python syntax.

## Principles Not Followed
*   **Strict "Felt Need":** The rigid pedagogical principle of "making the learner strictly feel the need" before introducing a concept was intentionally dropped. Attempting to enforce this would have added unnecessary complexity and length to the feature. The design prioritizes keeping the feature simple, meaningful, and accessible, demonstrating that a less rigid approach can still deliver strong pedagogical value.
