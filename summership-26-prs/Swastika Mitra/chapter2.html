Chapter 2 · Reading

Back to the Pantry

Reading isn't creating — it's collecting what's already been kept safe.

The Read Concept

The Spice Is Still There

One or two weeks later, someone orders a recipe that needs the same spice. But this time Rahul doesn't panic — he knows the spice is safely stored in the pantry. He just walks over, finds the jar he labeled weeks ago, and it's still there, still exactly right.

That's exactly what the open() function in read mode does — it doesn't make anything new, just goes back for something already saved. Reading isn't about creating new data; it's collecting data that's already been kept safe.

One rule: the file must already exist. Python won't create it, won't guess, won't fill in blanks — it just expects the file to be there and lets you start reading from the beginning.

The Nine-Hundred-Page Log

The chef assigns Rahul one more task: find every spice formula the kitchen has ever written. All the spice blends are written in a single log which has nine hundred pages. Rahul thought of bringing the whole log all at once. But here's the twist — when he brings the whole log, the counter is a mess. He cannot find anything, and no real work can be done.

The problem was never reading the pages. It was carrying too much all at once.

Same thing happens in Python. You can load a whole file into RAM in one go. Fine for a small file. But for something huge, like a 2 GB log file, the program just crashes with a MemoryError. And the fix isn't a bigger computer — it's reading it smarter.

Four Ways to Bring Pages to the Counter

By midnight, Rahul works out four ways to bring pages from the pantry to his counter — and each one matches a real Python reading method. Click each strategy to expand it.

f.read() — reads the entire file into one big string. Fine for small files, risky for huge ones, since it uses memory equal to the file's whole size.

contents = f.read()
print(contents)

f.read(n) — reads exactly n characters, then stops, remembering where to pick up next time.

chunk = f.read(100)   # first 100 characters
more  = f.read(100)   # next 100 characters

f.readline() — reads one line at a time. An empty string means there's nothing left — that's how you know the file has ended.

line = f.readline()
while line != "":
    print(line)
    line = f.readline()

for line in f: — reads the file line by line, using barely any memory no matter how big the file is. This is the safest, most common way to read large text files.

for line in f:
    print(line.strip())
Kitchen Strategy Python Method Best For
Whole carton f.read() Small files only
Fixed armful f.read(n) Controlled chunk sizes
One sheet f.readline() Line-by-line with manual loop
Endless pages for line in f: Large files — safest choice
Chef's tip: For a 900-page log (or any huge file), always prefer for line in f:. Your counter — RAM — stays clean and usable.
