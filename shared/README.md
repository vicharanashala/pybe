# Shared code, authored teaching flows

The shared layer supplies infrastructure and reusable interactions. It does **not** prescribe a universal lesson sequence.

- Keep every study and authored exercise. Keep story order, pacing, discovery activities, and the original timing of concept and syntax reveals.
- Select or compose shared components to fit the study. Do not turn a bespoke story into a generic reasoning/reveal/code template.
- The guided player is used only for collections that already had that exact three-stage structure. Sequence-based stories use their original ordered step data.
- Preserve special interactions, animations that carry teaching meaning, diagrams, simulations, and narrative milestones. Change them only when necessary to fix a demonstrated problem or support integration.
- Remove reward systems: points, scores awarded to learners, stars, ranks, and achievement badges. Keep meaningful feedback, hints, completion, narrative evidence, and labels inside explanatory diagrams. A CSS class named `badge` is not sufficient evidence of a reward.
- Flight 218 is a reference example: one continuous investigation, seven chapters, story-driven reasons for Python, the notebook, recorder, investigation board, and narrative closure. Its native adapter runs the original authored scripts; its HTML source remains unchanged and is protected by a hash check. Browser verification traverses all seven chapters.
- A study enters the integrated registry only after its original flow and special interactions have a working replacement and have been checked. Source code remains available while migration proceeds.

New submissions still go in `new-pr-submissions/`.
