## 1. Executive Summary

This report evaluates **The Sorting Investigation** for inclusion as an educational case study in the official PyBe repository.

The project introduces Python's `sorted()` function through a historically grounded, story-driven investigation set at Scutari Hospital during the Crimean War (1854–1856). Eight screens connect evidence, a tactile adjacent-swap game, four algorithm visualizations, an independent conceptual bridge to TimSort, Python practice, exercises with real local execution, and a final mission.

Prior notes record mentor approval of the topic and case-study direction in principle. The current build has been verified with **62/62 Python tests**, **451/451 JavaScript interaction assertions**, and a clean loopback API/browser pass. Technical claims in this report are deliberately limited to what was implemented and measured.

## 2. Pedagogical Distinction & Value to PyBe

1. **Cognitive friction via storytelling:** learners first experience unsorted ward records before seeing Python syntax.
2. **Tactile sorting game:** three levels use adjacent swaps only, matching the Bubble Sort operation shown later.
3. **Honest algorithm visualization:** Bubble, Insertion, Merge, and a clearly labelled simplified Timsort teaching model use the same ward sample. A separate **Connecting the Ideas** tab explains how natural runs, insertion, and merging relate to TimSort without changing the Timsort simulator.
4. **`sorted()` core focus:** ascending/descending order, immutability, `key=len`, `key=str.lower`, dictionary keys, and stability.
5. **Real-world application:** a Scutari emergency challenge applies descending priority sorting and real execution.
6. **Restricted local Python runner:** the terminal and final mission execute real Python through an AST allowlist, restricted builtins, loopback binding, timeouts, and output caps. This is **not** a secure sandbox.
7. **Honest comparison lab:** instrumented educational metrics are labelled separately, CPython Timsort move counts are reported as unavailable, and timings are single-shot local illustrations rather than a fair C-versus-Python race.

## 6. Explicit Caveats

1. The Python runner is a **restricted educational runner**, not a secure sandbox or hard security boundary.
2. Benchmark movement metrics are implementation-specific; CPython Timsort movement counts are intentionally unavailable. Local timings are illustrative only.
3. The Timsort Model and its conceptual bridge are teaching models, not reconstructions of CPython internals or galloping behavior.
4. The app requires Python 3.10+ because the server uses modern type syntax. Pillow and Node.js are test-only dependencies.
5. Generated bytecode and exact duplicate historical image files are exclusion candidates; no files were deleted during this audit.
